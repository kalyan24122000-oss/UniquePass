# UniquePass Generator

A fully functional, cryptographically secure password generator Chrome Extension with a Python (FastAPI) backend. 

The extension generates passwords using Python's `secrets` module on the backend. It guarantees **global uniqueness** for all passwords generated by this application by calculating a SHA-256 fingerprint of the password and enforcing a `UNIQUE` constraint in the local SQLite database. **Plaintext passwords are never stored.**

## Technology Stack
- **Frontend:** Vanilla JS, HTML5, CSS3 (Manifest V3 Chrome Extension)
- **Backend:** Python 3, FastAPI, SQLite

## Project Structure
- `backend/`: FastAPI Python server code and SQLite integration.
- `extension/`: Chrome Extension source code.

## Backend Setup

1. Open your terminal and navigate to the `backend` directory:
   ```bash
   cd backend
   ```
2. Install the required Python dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Start the FastAPI server:
   ```bash
   python main.py
   ```
4. On the first run, the SQLite database (`passwords.db`) will be automatically created.

## Chrome Extension Setup

1. Open Google Chrome.
2. Navigate to `chrome://extensions/` in the URL bar.
3. Enable **Developer mode** (toggle switch in the top right corner).
4. Click **Load unpacked**.
5. Select the `extension` folder from this project directory.
6. Ensure your Python backend is running.
7. Pin the extension to your toolbar and click the UniquePass icon to generate secure passwords!

## Security & Uniqueness Mechanism

- **Generation:** Passwords are generated using the `secrets.choice()` method which utilizes the OS's cryptographically secure pseudo-random number generator (CSPRNG) without modulo bias.
- **Storage:** The backend never stores plaintext passwords. It only stores a one-way SHA-256 hash.
- **Uniqueness Check:** The database schema enforces a `UNIQUE` constraint on the hash column. When a password is generated, it attempts to insert the hash atomically. If a race condition or collision occurs, SQLite throws an `IntegrityError`, causing the backend to silently discard the generation and try again. This ensures every successfully returned password is mathematically guaranteed to have never been output by this backend instance before.
